# RFML Studio Master Functional Brief

**Version:** v1.2
**Updated:** 27 August 2026

> MASTER STUDIO FILE. This brief consolidates the RFML Studio design environment, archive, provenance, visual extraction, typography archive and living Visual DNA requirements.

## 1. Purpose

RFML Studio is the creative and archival environment for Reggae Framed My Life. It is not simply a drawing application or an RFML branded alternative to generic design software.

Studio should connect research, visual analysis, experimentation, original design, physical production and permanent archive. It should preserve the lineage of ideas while giving the designer freedom to create work that may be precise, irregular, contradictory, distressed, oversized, awkward or deliberately inconsistent.

The tool creates consistency in process, memory and provenance, not forced consistency in appearance.

## 2. Core Principle: Controlled Inconsistency

RFML Studio must never decide what good RFML design looks like.

Do not automatically beautify, centre, align, regularise, harmonise or force a house style. Snapping, grids and alignment tools should be optional. Different releases may use radically different typography, colour, composition and image treatment.

The archive should allow recurring characteristics to emerge from actual research and design work rather than prescribing them in advance.

## 3. Core Workflow

The long term Studio workflow is:

ARCHIVE → UNDERSTAND → DECONSTRUCT → STORY → MOODBOARD → GENERATE → CURATE → ORIGINAL ART → IP CHECK → SAMPLE → RELEASE → ARCHIVE

Research and provenance remain connected throughout. A source discovered during research can become an extracted element, an experiment, a transformed RFML element, a design, a production file and finally a released object without losing its history.

## 4. Studio Home

The opening screen should feel like a creative studio and archive table rather than a corporate dashboard.

Primary areas:
• New Work
• Workbench
• Archive
• Materials
• Collections
• Visual DNA
• Production
• Vault

Recent visual work should dominate the home experience.

## 5. Main Design Canvas

The canvas should support an infinite or expandable workspace, free placement, layers, groups, locking, hiding, opacity, rotation, scaling, cropping, masks, blend modes, optional guides, optional snapping, undo, version history, duplication and variations.

Objects may extend beyond conventional production boundaries. Destructive looking effects should remain editable wherever possible.

## 5A. Direct Manipulation First

Direct manipulation is a foundational Studio interaction rule.

If the user can see an object, they should normally be able to touch or click it and manipulate it directly. Panels are secondary.

On touch devices the target behaviour is:
• Tap to select
• One finger drag to move
• Two finger pinch to scale
• Two finger twist to rotate
• Two fingers on empty workspace to pan or zoom the canvas
• Long press or a compact contextual control for duplicate, stacking, lock, hide and delete

Large background elements must be lockable. Overlapping objects must remain easy to select. Interactive hit areas should be forgiving enough for thin lines, small lettering and transparent elements.

During movement, Studio may temporarily simplify expensive visual effects to preserve responsive interaction. The artwork should follow the user's hand continuously.

The principle is:

SEE IT → TOUCH IT → MOVE IT

Studio should feel closer to moving physical material around a working table than operating a traditional software control panel.

## 6. Multi Surface and Object Design

Studio should understand a garment as one physical object rather than unrelated front and back rectangles.

2D Artwork Mode and 3D Object Mode are equal views of the same underlying design data. 3D is a foundational requirement, not a later mockup feature.

Initial garment surfaces:
• Front
• Back
• Left sleeve
• Right sleeve
• Collar and neck
• Hem

Artwork Mode provides accurate flat or unwrapped surfaces for precise placement. Object Mode provides a live rotatable 3D garment preview driven by the same artwork and coordinates.

Changes in Artwork Mode should update Object Mode immediately. Where technically possible, artwork must be able to cross front, side, sleeve and back areas continuously through a shared UV mapped garment surface.

The first production garment target is a T shirt. The architecture must support additional garment and object templates later, including shirts, jackets, hoodies, posters, record sleeves, books, labels, packaging, boxes and fabric panels.

Advanced cloth physics, realistic drape, embroidery depth and material simulation may arrive later, but the 2D ↔ 3D relationship must exist from the first proper Studio build.

## 7. Image and Print Tools

Support upload, crop, rotate, mask, cutout, background removal, threshold, monochrome, duotone, posterisation, halftone, grain, blur, photocopy degradation, screen print simulation, overprint, colour separation, transparency, distortion and repetition.

Texture should be a first class material. The library should support paper, ink, fabric, paint, ageing, dust, scratches, tape, handwriting, stamps, screen print textures and registration errors.

## 8. Typography System

Typography must be highly free and treated as both language and image.

Support individual letter manipulation, mixed fonts within words, mixed sizes, different baselines, character rotation, vertical type, circular type, type on paths, distortion, outline, fill, stroke, tracking, leading, condensed and expanded treatments, masks and partially obscured type.

Studio should not assume that legibility or consistency is always the primary goal.

## 9. Colour

Provide conventional colour tools without enforcing a permanent RFML palette.

Support colour sampling from research, saved colours, project palettes, research sourced palettes, spot colours, CMYK and RGB preview and limited ink simulation. Palettes should be extractable from photographs, sleeves, posters and other visual references.

## 10. Research Integration and Provenance

Every design can have sources attached to it, including photographs, album artwork, posters, advertisements, books, magazines, objects, locations, interviews, films, archive discoveries, personal memories and written observations.

A source may influence a design without appearing visibly in the final work.

Every source and extracted element must retain provenance. The system should always be able to answer: Where did this come from?

## 11. Visual Extraction Engine

This is a core Studio capability.

When an image, scan, photograph, artwork or document enters Studio, analyse it for potentially useful visual components. Proposed extractions should be shown to the user for approval. Studio must not automatically flood the permanent archive.

Potential extraction categories:
• Typography and lettering
• Colour palettes
• Photographs
• Illustrations
• Symbols and marks
• Shapes
• Borders and frames
• Patterns
• Textures
• Layout and composition
• Print characteristics
• Repeated motifs
• Production characteristics

Where technically possible, allow elements to be isolated. Lettering can become a transparent visual asset, texture a reusable layer, colour combinations a palette and borders reusable graphic material.

The original source must remain untouched and permanently linked to every extraction.

## 12. Typography Archive

Typography requires its own searchable visual archive.

For each captured example store:
• Original source
• Extracted visual sample
• Type: font, lettering, handwriting, painted sign, stencil, typesetting or unknown
• Characteristics such as condensed, extended, heavy, light, italic, irregular, geometric, decorative, hand rendered, distressed, outlined or shadowed
• Arrangement such as horizontal, vertical, curved, stacked, rotated, scattered or mixed
• Research context
• Date discovered
• Notes
• Rights and provenance status
• Designs or experiments in which it is later used

If an exact font cannot be identified, Studio must not invent one. Preserve the visual example and describe its characteristics instead.

## 13. Composition Archive

Studio should archive visual arrangements as knowledge, not merely reusable templates.

Analyse symmetry and asymmetry, image dominance, type hierarchy, negative space, density, alignment, overlap, cropping, edge interaction, scale relationships, repetition and apparent registration errors.

Composition references should help the designer understand historical and emerging visual language without encouraging direct copying.

## 14. Source vs RFML Classification

Maintain a strict visible distinction between:

SOURCE MATERIAL
Historical, cultural, archival, found or third party material.

RFML CREATED MATERIAL
Original material produced by RFML.

RFML TRANSFORMED MATERIAL
Material developed through transformation of research or source material.

The classification and lineage must remain attached as material moves through Studio.

## 15. Design Analysis and Living Visual DNA

Studio should analyse RFML's own experiments and completed designs using the same extraction system.

Record typography, colours, textures, composition characteristics, image treatments, marks, production methods and recurring relationships.

Over time Studio should reveal patterns such as:
• a treatment appearing across multiple designs
• a recurring colour relationship
• typography characteristics connected to a research period
• a composition device first appearing in one experiment and returning later

These are observations, never rules.

The goal is a living, evidence based map of RFML's visual DNA that emerges from the work rather than being predetermined.

## 16. Visual Archive and Search

The archive should feel like a huge visual reference wall rather than a database table.

Users should move fluidly between Source, Element, Design, Experiment and Collection.

Support natural language and filtered visual search, for example:
• Show hand drawn typography
• Show typography from 1970s research
• Show distressed printing
• Show irregular compositions
• Show yellow, red and black palettes
• Show everything connected to RFML 003
• Show visual ideas extracted but never used

Every result should remain traceable back to its source.

## 17. Physical Composition Table

Include a freeform digital table for early composition and discovery.

Photographs, scans, record sleeves, type, scraps, notes, textures, palettes and extracted elements can be thrown onto a large workspace before the user chooses a product format.

This space is intentionally less structured than the production canvas. It should support juxtaposition, accidental relationships and visual thinking.

## 18. Design DNA Panel

Each project can contain a Design DNA panel recording:

• Origin: what initiated the design
• Sources: research objects and references
• Discoveries: what was learned
• Transformations: how source material changed
• Versions: how the work evolved
• Production: how it could or did get made

This creates an archive of thinking, not merely files.

## 19. Experiment and Version System

From any design the user can create an experiment without altering the parent. Experiments can branch repeatedly and form a visible family tree.

Rejected and failed experiments should be preservable. Studio should not require deletion simply because a direction was abandoned.

Compare Mode should allow simultaneous viewing of front, back, details, garment views, colour variants, typography variants and artwork treatments without numerical creative scoring.

## 20. Detail Hierarchy

Allow elements to be tagged Primary, Secondary, Hidden or Micro Detail. These tags describe intended discovery hierarchy and do not automatically alter the artwork.

## 21. Production Awareness

Studio should understand production methods including screen printing, DTG, embroidery, woven labels, patches, heat transfer, dye sublimation, fabric printing, appliqué, vinyl, paper printing and specialist finishing.

It may warn when something is technically difficult, but should not prevent deliberate rule breaking.

Garment projects should include dedicated areas for neck print, neck label, hem label, sleeve mark, internal label, edition information, artist attribution and production information.

## 22. Rights and IP Awareness

Research material is evidence and inspiration, not automatically commercial artwork.

Every visual reference should be capable of storing creator, photographer, illustrator, label, source, rights holder, permission status, research only status and public reproduction status.

Source material and extracted elements should carry rights metadata forward into experiments and designs. Studio should flag unresolved provenance or rights questions before commercial production, while preserving the research record.

## 23. Presentation and Export

A design should be capable of generating a restrained RFML presentation board using combinations of front view, back view, detail crop, object mockup, source material, title, design number, collection and concept statement.

Export should support PNG, JPG and PDF plus high resolution transparent artwork, print sized artwork, individual surface exports and colour separated artwork where applicable.

Archive export should package the design, sources, metadata, versions, production notes and presentation images.

## 24. Design Identification and Archive

Every piece receives a persistent Studio identity, for example RFML 001, EXP 001, FRAME 001 or AE 01. Versions sit beneath the identity.

The permanent archive should retain the full history of research, experiments, design decisions, production and release rather than only the final approved artwork.

## 25. Interface Direction

The interface should be quiet, precise, editorial, functional and slightly industrial.

Prefer warm neutral working surfaces, black typography, fine rules, strong whitespace, compact controls and small technical labels.

Avoid generic SaaS styling, excessive rounded cards, gratuitous gradients, bright interface colours, cartoon icons, gamification and over designed dashboards.

The work itself provides the colour and disruption.

## 27. Test of Success

RFML Studio succeeds if two completely different RFML designs can be created inside it without either looking like it came from a software template.

It succeeds if a user can manipulate artwork naturally, move between precise 2D Artwork Mode and live 3D Object Mode without rebuilding the design, and place a single artwork treatment across multiple garment surfaces while preserving continuity.

It succeeds if a visual discovery can be traced from original research source through extraction, transformation, experiment, design, production and release.

It succeeds if, after substantial research and creative work, Studio can reveal RFML's emerging visual DNA without ever turning those observations into mandatory design rules.

The human provides the judgement. Studio provides tools, surfaces, materials, memory, provenance and production knowledge.
